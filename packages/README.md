# packages/

Shared code consumed by apps — ships **empty** in the template (ADR-0005).
Every `packages/<pkg>/` directory is generated by the scaffold step
(`set-project-stack` → `scaffold_project_files`, or `dev-flow-scaffold-project`)
from `.template/scaffold/packages/<runtime>/`, so no reference libraries are
committed here.

## Convention

- Each shared library lives at `packages/<pkg>/` (grouped by runtime if
  multiple stacks share code, e.g. `packages/dotnet/`, `packages/node/`).
- Apps declare a library via the optional `dependsOn: ["<pkg>"]` field in
  `infra/deployment/apps.json`. A `packages/<pkg>/**` change then rebuilds and
  redeploys every dependent app (deployable-changes gate in CI).
- `packages/**` is build-time only — never deployed, never ported, no k8s
  manifests.

## Default node skeletons (JS/TS stack)

For JS/TS stacks, `scaffold_project_files` materializes three generic skeletons
from `.template/scaffold/packages/node/` (auth, UI, API-client — the shape that
a typical app trio needs). The `<pkgName>` placeholder in each shape is
substituted with the package name; content is stack-generic and meant to be
implemented per product:

| Shape        | Purpose                        |
| ------------ | ------------------------------ |
| `auth-lib`   | password hashing, token checks |
| `ui-kit`     | UI primitives (Button, tokens) |
| `api-client` | typed fetch client             |

Non-JS/TS stacks get an info note — their package shapes are generated per
stack by `dev-flow-scaffold-project`, never guessed.

## Adding a library

1. Run `set-project-stack` / the scaffold to generate the package skeleton for
   the resolved runtime, or copy `.template/scaffold/packages/<runtime>/` to
   `packages/<pkg>/` and substitute `<pkgName>`.
2. Register the consuming app's dependency in `apps.json` (`dependsOn`).
3. Reference the package from `apps/<appId>/src`. For Node apps use a `file:`
   dependency in the app's `package.json` (per-app lockfiles, existing Docker
   build contexts); Docker builds use the repo root as the build context so
   `file:` deps on `../../packages/...` resolve inside the image.
