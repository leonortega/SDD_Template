# packages/

Shared code consumed by apps — ships **empty** in the template.

This is a template, not a product: every `packages/<pkg>/` directory is generated by the
scaffold step (`dev-flow-scaffold-project`) from the selected stack, so no reference
libraries are committed here.

## Convention

- Each shared library lives at `packages/<pkg>/` (grouped by runtime if multiple stacks
  share code, e.g. `packages/dotnet/`, `packages/node/`).
- Apps declare a library via the optional `dependsOn: ["<pkg>"]` field in
  `infra/deployment/apps.json`. A `packages/<pkg>/**` change then rebuilds and redeploys
  every dependent app (deployable-changes gate in CI).
- `packages/**` is build-time only — never deployed, never ported, no k8s manifests.

## Adding a library

1. Run `set-project-stack` / the scaffold to generate the package skeleton for the
   resolved runtime.
2. Register the consuming app's dependency in `apps.json` (`dependsOn`).
3. Reference the package from `apps/<appId>/src` per the runtime's project/workspace
   mechanism (project references, npm/yarn workspaces, etc.).
